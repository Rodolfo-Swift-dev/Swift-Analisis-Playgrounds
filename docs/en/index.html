REFERENCE GUIDE

Swift: keywords, behavior and limits

20 chapters · syntax · behavior · limits · official terminology

Examples are short usage fragments. Some depend on types or variables defined in their chapter.

How to use this guide

Complete guide based on the 20 numbered playgrounds of this project.

Each chapter answers three questions:

  1. What keyword or syntax should I recognize?
  2. What behavior does it produce?
  3. What is your limit, risk or rule?

English names marked as Official nomenclature correspond to the terms used by The Swift Programming Language. It is advisable to learn them because they are the ones that appear in the documentation, in the compiler diagnostics and in technical conversations.

1. TypeAlias

Open playground

Objective: use alternative names to better express the intent of a type without creating a new type.
Official terminology View terms
•
Type Alias — alternative name for an existing type.
•
Type Alias Declaration — statement made with typealias.

Standard and custom type aliases

typealias Celsius = Double View details
Behavior
Give an alternative name to Double.
Limit or caution
It does not create a new type or avoid mixing it with others Double.
Usage example
typealias Celsius = Double
let temperature: Celsius = 21.5
typealias CharacterName = String View details
Behavior
Better expresses the meaning of a data.
Limit or caution
Maintain all rules and operations String.
Usage example
typealias CharacterName = String
let hero: CharacterName = "Ayla"
typealias Client = User View details
Behavior
Allows you to refer to your own type with another name.
Limit or caution
Client and User are still exactly the same type.
Usage example
struct User { let name: String }
typealias Client = User
let client = Client(name: "Ana")
Complex type aliases View details
Behavior
Reduces noise in long signatures.
Limit or caution
An unclear name can hide useful information.
Usage example
typealias Completion = (Result<String, Error>) -> Void
func load(completion: Completion) { }

Essential behavior:

typealias Celsius = Double
let temperature: Celsius = 12.2

Essential limit: typealias improves readability, but does not add additional validation, identity, or type safety. For this you need to create a struct, class or enum.

Common mistake

•
Believing that typealias creates a distinct type. typealias UserID = String only adds another name: a UserID still accepts any String.

Open playground

Objective: group and decompose small amounts of related values, even when they have different types.
Official terminology View terms
•
Tuples — groupings of several values into a single composite value.
•
Tuple Decomposition — decomposition of a tuple into constants or variables.
•
Named Tuple Elements — elements identified by names.
•
Ignoring Parts of a Tuple — discarding elements by _.
•
Multiple Return Values — return multiple values from a function.

Declaration and access

(String, Int, Bool) View details
Behavior
Groups values of different types and in a fixed order.
Limit or caution
The quantity, order, and types are part of the type of the tuple.
Usage example
let person: (String, Int, Bool) = ("Ana", 28, true)
tuple.0, tuple.1 View details
Behavior
Access by position.
Limit or caution
Loses clarity when there are many elements.
Usage example
let person = ("Ana", 28)
print(person.0) // Ana
(name: String, age: Int) View details
Behavior
Assign names to elements.
Limit or caution
Names do not convert the tuple to a reusable nominal type.
Usage example
let person = (name: "Ana", age: 28)
tuple.name View details
Behavior
Access through the element label.
Limit or caution
The tag must exist in that tuple.
Usage example
let person = (name: "Ana", age: 28)
print(person.name)

Decomposition

let (name, age) = tuple View details
Behavior
Decomposes all values.
Limit or caution
The pattern structure must match the tuple.
Usage example
let point = (3, 7)
let (x, y) = point
let (name, _) = tuple View details
Behavior
Ignore unnecessary elements.
Limit or caution
_ discard that value.
Usage example
let user = ("Ana", 28)
let (name, _) = user

Composition and returns

((...), (...)) View details
Behavior
Allows nesting tuples.
Limit or caution
Access becomes difficult to read quickly.
Usage example
let result = (user: (name: "Ana", age: 28), active: true)
func f() -> (A, B) View details
Behavior
Returns several values.
Limit or caution
For large or stable models, a separate type is preferable.
Usage example
func bounds() -> (min: Int, max: Int) {
    (0, 100)
}
(result: Int?, error: String?) View details
Behavior
Model two related outcomes.
Limit or caution
May represent invalid states; Result or throwable errors are safer.
Usage example
let operation: (result: Int?, error: String?) =
    (nil, "Division by zero")

Present uses: group related data, return multiple values, decompose results and handle small temporary groups.

Essential limit: a tuple is of fixed size and is not a dynamic collection. When the model needs methods, validations or a clear identity, it should be preferred struct.

Common mistake

•
Treating a tuple as though it conformed to Sequence or were a collection. Operations such as sorted() cannot be applied directly; a pair of optionals for success and failure can also represent invalid states.

3. Optional

Open playground

Objective: represent absence of value and choose a safe strategy for accessing optional data.
Official terminology View terms
•
Optionals — values that may contain a piece of data or nil.
•
Optional Binding — conditional extraction using if let or guard let.
•
Forced Unwrapping — forced extraction through !.
•
Nil-Coalescing Operator — alternative value using ??.
•
Optional Chaining — conditional access via ?..
•
Implicitly Unwrapped Optional — an optional declared as T!; it is not the same as applying ! to a T?.

Representing absence

T? View details
Behavior
Represents Optional<T>: may contain a T or nil.
Limit or risk
It cannot be used directly as a T.
Usage example
var nickname: String? = "Rodo"
nickname = nil
nil View details
Behavior
Indicates absence of value.
Limit or risk
It can only be assigned to an optional.
Usage example
var selectedUser: User? = nil

Safe unpacking

Optional Binding if let value = optional View details
Behavior
Unpack if a value exists.
Limit or risk
value lives only in the corresponding scope.
Usage example
if let name = nickname {
    print(name)
}
Optional Binding guard let value = optional else { return } View details
Behavior
Validates and makes the value available in the rest of the scope.
Limit or risk
The else block must exit with return, break, continue, or throw.
Usage example
guard let name = nickname else { return }
print(name)

Alternatives and risks

Forced Unwrapping optional! View details
Behavior
Extract the value without checking it.
Limit or risk
Produces an error during execution if it contains nil.
Usage example
let count = nickname!.count // Traps if nickname is nil
Nil-Coalescing Operator — optional ?? defaultValue View details
Behavior
Use the value or supply a default one.
Limit or risk
Both sides must produce compatible types.
Usage example
let displayName = nickname ?? "No name"
Optional Chaining optional?.member View details
Behavior
Accesses the member only if the value exists.
Limit or risk
If any step is nil, the entire chain produces nil.
Usage example
let firstLetter = nickname?.first
optional != nil View details
Behavior
It only checks for existence.
Limit or risk
Afterwards you still need to unpack to use the value.
Usage example
if nickname != nil {
    print("A value exists, but it is still String?")
}

Operations and collections

optional.map { ... } View details
Behavior
Transform the content only if it exists.
Limit or risk
The result remains optional.
Usage example
let length = nickname.map { $0.count }
dictionary[key] View details
Behavior
Search for a value by key.
Limit or risk
It always returns an optional because the key might not exist.
Usage example
let capitals = ["CL": "Santiago"]; let city = capitals["CL"]

Recommended safe flow:

guard let value = optional else {
    return
}
// value is no longer optional here

Safety order:

  1. prefer if let, guard let, ?? or ?..
  2. Use ! only when the existence of the value is guaranteed by a verifiable rule.

Common mistake

•
Force-unwrapping with ! without a verifiable guarantee. If the value is nil, the program traps at runtime; a fallback with ?? should not silently hide a missing required value either.

•
Order, indexes or duplicates → Array.

•

5. ControlFlow

Open playground

Objective: deciding what code is executed, repeating operations, and abandoning a flow when its conditions are not met.
Official terminology View terms
•
Conditional Statements — conditional sentences.
•
If Statement — sentence if.
•
Switch Statement — sentence switch.
•
For-In Loops — cycles for-in.
•
While Loops — cycles while and repeat-while.
•
Early Exit — early departure via guard.
•
Where Clause — additional condition applied to a pattern or iteration.
•
Control Transfer Statements — continue, break, fallthrough, return and throw.

Conditions

if condition View details
Behavior
Executes a block when the Bool is true.
Limit or rule
The condition must be Bool; Swift does not support “truthy” values.
Usage example
if temperature > 30 {
    print("It is hot")
}
else if View details
Behavior
Evaluate another condition if the previous ones failed.
Limit or rule
Only the first true branch is executed.
Usage example
if score >= 90 {
    print("Excellent")
} else if score >= 60 {
    print("Passed")
}
else View details
Behavior
Run the final alternative.
Limit or rule
It has no condition.
Usage example
if isConnected {
    loadData()
} else {
    showOfflineMessage()
}

Early exit

guard condition else View details
Behavior
Requires the condition to be true to continue.
Limit or rule
The else must leave the scope.
Usage example
guard isAuthenticated else { return }
showProfile()
guard let View details
Behavior
Unpack an optional and allow it to be used later.
Limit or rule
Fails and exits when the value is nil.
Usage example
guard let user = currentUser else { return }
print(user.name)

Selection by cases

switch value View details
Behavior
Compare a value with patterns or cases.
Limit or rule
It must be exhaustive.
Usage example
switch status {
case .success: print("OK")
case .failure: print("Error")
}
case View details
Behavior
Defines a pattern accepted by switch.
Limit or rule
There is no implicit fall to the following case.
Usage example
switch number {
case 0: print("Zero")
default: print("Other")
}
default View details
Behavior
Cover the remaining values.
Limit or rule
You can hide new instances of an enum; Skipping it helps detect changes.
Usage example
switch number {
case 0: print("Zero")
default: break
}
case ... where condition View details
Behavior
Add a filter to the pattern.
Limit or rule
The condition is evaluated after the pattern is matched.
Usage example
switch age {
case let value where value >= 18: print("Adult")
default: print("Minor")
}
break View details
Behavior
Ends the current block or cycle.
Limit or rule
It does not automatically exit external scopes.
Usage example
for number in numbers {
    if number < 0 { break }
}

Iteration

for value in sequence View details
Behavior
Go through a sequence.
Limit or rule
The order depends on the collection.
Usage example
for name in names {
    print(name)
}
for value in sequence where ... View details
Behavior
Filter during the tour.
Limit or rule
It does not modify the original collection.
Usage example
for number in numbers where number.isMultiple(of: 2) {
    print(number)
}
_ View details
Behavior
Ignores the current element.
Limit or rule
The value is not available within the block.
Usage example
for _ in 1...3 { print("Hello") }

Conditional loops

while condition View details
Behavior
Check and then run repeatedly.
Limit or rule
It may never run or produce an infinite loop.
Usage example
while attempts < 3 {
    attempts += 1
}
repeat { ... } while condition View details
Behavior
Run and then check.
Limit or rule
It is always executed at least once.
Usage example
repeat {
    attempts += 1
} while attempts < 3

Key comparison:

while        = preguntar → ejecutar
repeat-while = ejecutar → preguntar

Common mistake

•
Writing a non-exhaustive switch, referring to a different variable inside where, or creating a loop whose condition never changes. The compiler catches some cases, but it cannot prove that every loop will terminate.

•

function for String  ┐
function for Int     ├─→ one generic function
function for Double  ┘

Essential limit: a generic does not allow using any operation on T. This capacity must first be guaranteed through a protocol restriction.

Common mistake

•
Mixing values of different generic types, introducing generic parameters that express no useful relationship, or implementing pop() as if an element always existed. An empty stack should return an optional or report failure safely.

Complete flow:

enum Error          identifies the possible failures
throws              declares that a function may fail
throw               produces the specific failure
try                 attempts to execute the function
do                  contains the attempt
catch               receives and handles the error

Integrated example:

enum DatabaseError: Error {
    case userExists
    case invalidName
}

func saveUser(name: String) throws {
    guard !name.isEmpty else {
        throw DatabaseError.invalidName
    }
}

do {
    try saveUser(name: "")
} catch DatabaseError.invalidName {
    print("Invalid name")
} catch {
    print("Other error: \(error)")
}

Fundamental difference:

try  + do/catch = preserves and handles the error
try?            = returns only a value or nil; error details are lost

Common mistake

•
Believing that a do block does not start when an error is later thrown, using try? when the cause matters, or using try! without an absolute guarantee. do runs until throw, then control moves to a matching catch.

Behavior

Treats a subclass instance as its superclass or performs another guaranteed cast.

Behavior
Attempts a downcast and returns an optional.
Limit or risk
It must be unwrapped and returns nil if the cast fails.
Usage example

    dog.bark()
}
as! — Forced Downcast View details
Behavior
Asserts that the downcast will succeed.
Limit or risk
It traps at runtime if the actual type does not match.
Usage example
let dog = animal as! Dog // Traps if it is not a Dog

Safe pattern:

if let fish = animal as? Fish {
    fish.respirarBajoAgua()
}

Polymorphism:

[Animal] can contain Dog, Cat, and Bird
          ↓
as? recovers the concrete subtype
          ↓
allows use of the subtype-specific method

Rules:

•
is checks a type.
•
as upcasts to a more general type.
•
as? attempts a safe downcast.
•
as! forces a downcast and can trap at runtime.
•
Type casting changes the typed view of an instance; it does not create another object.

Common mistake

•
Confusing type casting with value conversion. as? cannot turn "123" into an Int; use Int("123"). A forced downcast with as! traps when the runtime type does not match, and printing a Void-returning function only displays ().
