1. TypeAlias

Abrir playground

Objetivo: usar nombres alternativos para expresar mejor la intención de un tipo sin crear un tipo nuevo.
Nomenclatura oficial Ver términos
•
Type Alias — nombre alternativo para un tipo existente.
•
Type Alias Declaration — declaración realizada con typealias.

Alias de tipos estándar y personalizados

typealias Celsius = Double Ver detalle
Comportamiento
Da un nombre alternativo a Double.
Límite o cuidado
No crea un tipo nuevo ni evita mezclarlo con otros Double.
Ejemplo de uso
typealias Celsius = Double
let temperature: Celsius = 21.5
typealias CharacterName = String Ver detalle
Comportamiento
Expresa mejor el significado de un dato.
Límite o cuidado
Conserva todas las reglas y operaciones de String.
Ejemplo de uso
typealias CharacterName = String
let hero: CharacterName = "Ayla"
typealias Client = User Ver detalle
Comportamiento
Permite referirse a un tipo propio con otro nombre.
Límite o cuidado
Client y User siguen siendo exactamente el mismo tipo.
Ejemplo de uso
struct User { let name: String }
typealias Client = User
let client = Client(name: "Ana")
Alias de tipo complejo Ver detalle
Comportamiento
Reduce ruido en firmas largas.
Límite o cuidado
Un nombre poco claro puede ocultar información útil.
Ejemplo de uso
typealias Completion = (Result<String, Error>) -> Void
func load(completion: Completion) { }

Comportamiento esencial:

typealias Celsius = Double
let temperature: Celsius = 12.2

Límite esencial: typealias mejora la lectura, pero no agrega validación, identidad ni seguridad de tipo adicional. Para eso se necesita crear un struct, class o enum.

Error frecuente

•
Creer que typealias crea un tipo distinto. typealias UserID = String solo agrega otro nombre: un UserID sigue aceptando cualquier String.

2. Tuplas

Abrir playground

Objetivo: agrupar y descomponer pequeñas cantidades de valores relacionados, incluso cuando tienen tipos diferentes.
Nomenclatura oficial Ver términos
•
Tuples — agrupaciones de varios valores en un único valor compuesto.
•
Tuple Decomposition — descomposición de una tupla en constantes o variables.
•
Named Tuple Elements — elementos identificados mediante nombres.
•
Ignoring Parts of a Tuple — descarte de elementos mediante _.
•
Multiple Return Values — retorno de varios valores desde una función.

Declaración y acceso

(String, Int, Bool) Ver detalle
Comportamiento
Agrupa valores de tipos distintos y en un orden fijo.
Límite o cuidado
La cantidad, el orden y los tipos forman parte del tipo de la tupla.
Ejemplo de uso
let person: (String, Int, Bool) = ("Ana", 28, true)
tuple.0, tuple.1 Ver detalle
Comportamiento
Accede por posición.
Límite o cuidado
Pierde claridad cuando hay muchos elementos.
Ejemplo de uso
let person = ("Ana", 28)
print(person.0) // Ana
(name: String, age: Int) Ver detalle
Comportamiento
Asigna nombres a los elementos.
Límite o cuidado
Los nombres no convierten la tupla en un tipo nominal reutilizable.
Ejemplo de uso
let person = (name: "Ana", age: 28)
tuple.name Ver detalle
Comportamiento
Accede mediante la etiqueta del elemento.
Límite o cuidado
La etiqueta debe existir en esa tupla.
Ejemplo de uso
let person = (name: "Ana", age: 28)
print(person.name)

Descomposición

let (name, age) = tuple Ver detalle
Comportamiento
Descompone todos los valores.
Límite o cuidado
La estructura del patrón debe coincidir con la tupla.
Ejemplo de uso
let point = (3, 7)
let (x, y) = point
let (name, _) = tuple Ver detalle
Comportamiento
Ignora elementos no necesarios.
Límite o cuidado
_ descarta ese valor.
Ejemplo de uso
let user = ("Ana", 28)
let (name, _) = user

Composición y retornos

((...), (...)) Ver detalle
Comportamiento
Permite anidar tuplas.
Límite o cuidado
El acceso se vuelve difícil de leer rápidamente.
Ejemplo de uso
let result = (user: (name: "Ana", age: 28), active: true)
func f() -> (A, B) Ver detalle
Comportamiento
Retorna varios valores.
Límite o cuidado
Para modelos grandes o estables es preferible un tipo propio.
Ejemplo de uso
func bounds() -> (min: Int, max: Int) {
    (0, 100)
}
(resultado: Int?, error: String?) Ver detalle
Comportamiento
Modela dos resultados relacionados.
Límite o cuidado
Puede representar estados inválidos; Result o errores lanzables son más seguros.
Ejemplo de uso
let operation: (result: Int?, error: String?) =
    (nil, "División por cero")

Usos presentes: agrupar datos relacionados, retornar varios valores, descomponer resultados y manejar pequeños grupos temporales.

Límite esencial: una tupla es de tamaño fijo y no es una colección dinámica. Cuando el modelo necesita métodos, validaciones o una identidad clara, se debe preferir struct.

Error frecuente

•
Tratar una tupla como si conformara Sequence o fuera una colección. No admite directamente operaciones como sorted(); tampoco conviene representar éxito y error con una pareja de opcionales que permita estados inválidos.

3. Optional

Abrir playground

Objetivo: representar ausencia de valor y elegir una estrategia segura para acceder al dato opcional.
Nomenclatura oficial Ver términos
•
Optionals — valores que pueden contener un dato o nil.
•
Optional Binding — extracción condicional mediante if let o guard let.
•
Forced Unwrapping — extracción forzada mediante !.
•
Nil-Coalescing Operator — valor alternativo mediante ??.
•
Optional Chaining — acceso condicional mediante ?..
•
Implicitly Unwrapped Optional — opcional declarado como T!; no es lo mismo que aplicar ! a un T?.

Representar ausencia

T? Ver detalle
Comportamiento
Representa Optional<T>: puede contener un T o nil.
Límite o riesgo
No se puede usar directamente como un T.
Ejemplo de uso
var nickname: String? = "Rodo"
nickname = nil
nil Ver detalle
Comportamiento
Indica ausencia de valor.
Límite o riesgo
Solo puede asignarse a un opcional.
Ejemplo de uso
var selectedUser: User? = nil

Desempaquetado seguro

Optional Binding — if let value = optional Ver detalle
Comportamiento
Desempaqueta si existe un valor.
Límite o riesgo
value vive solamente en el alcance correspondiente.
Ejemplo de uso
if let name = nickname {
    print(name)
}
Optional Binding — guard let value = optional else { return } Ver detalle
Comportamiento
Valida y deja disponible el valor en el resto del scope.
Límite o riesgo
El bloque else debe salir con return, break, continue o throw.
Ejemplo de uso
guard let name = nickname else { return }
print(name)

Alternativas y riesgos

Forced Unwrapping — optional! Ver detalle
Comportamiento
Extrae el valor sin comprobarlo.
Límite o riesgo
Produce un error en ejecución si contiene nil.
Ejemplo de uso
let count = nickname!.count // Falla si nickname es nil
Nil-Coalescing Operator — optional ?? defaultValue Ver detalle
Comportamiento
Usa el valor o entrega uno predeterminado.
Límite o riesgo
Ambos lados deben producir tipos compatibles.
Ejemplo de uso
let displayName = nickname ?? "Sin nombre"
Optional Chaining — optional?.member Ver detalle
Comportamiento
Accede al miembro solo si existe el valor.
Límite o riesgo
Si cualquier paso es nil, toda la cadena produce nil.
Ejemplo de uso
let firstLetter = nickname?.first
optional != nil Ver detalle
Comportamiento
Solo comprueba existencia.
Límite o riesgo
Después aún es necesario desempaquetar para usar el valor.
Ejemplo de uso
if nickname != nil {
    print("Existe, pero aún es String?")
}

Operaciones y colecciones

optional.map { ... } Ver detalle
Comportamiento
Transforma el contenido únicamente si existe.
Límite o riesgo
El resultado continúa siendo opcional.
Ejemplo de uso
let length = nickname.map { $0.count }
dictionary[key] Ver detalle
Comportamiento
Busca un valor por clave.
Límite o riesgo
Siempre devuelve un opcional porque la clave podría no existir.
Ejemplo de uso
let capitals = ["CL": "Santiago"]; let city = capitals["CL"]

Flujo seguro recomendado:

guard let value = optional else {
    return
}
// value ya no es opcional aquí

Orden de seguridad:

  1. Preferir if let, guard let, ?? o ?..
  2. Usar ! únicamente cuando la existencia del valor esté garantizada por una regla verificable.

Error frecuente

•
Forzar un opcional con ! sin una garantía verificable. Si el valor es nil, el programa termina en ejecución; un valor por defecto con ?? tampoco debe ocultar silenciosamente un dato obligatorio.

4. Colecciones

Abrir playground

Objetivo: seleccionar y operar correctamente con colecciones ordenadas, únicas o basadas en claves.
Nomenclatura oficial Ver términos
•
Collection Types — tipos de colección.
•
Arrays — colecciones ordenadas.
•
Sets — colecciones sin duplicados y sin orden definido.
•
Dictionaries — colecciones de pares clave-valor.
•
Set Operations — operaciones de conjuntos.
•
Hashable — requisito que permite identificar valores como claves o elementos de un set.

Array<Element>

[T] o Array<T> Ver detalle
Comportamiento
Colección ordenada de elementos del mismo tipo.
Límite o riesgo
Acepta duplicados.
Ejemplo de uso
var names: [String] = ["Ana", "Luis"]
array[index] Ver detalle
Comportamiento
Lee o modifica por posición.
Límite o riesgo
Un índice inválido produce error en ejecución.
Ejemplo de uso
let firstName = names[0]
count Ver detalle
Comportamiento
Entrega la cantidad de elementos.
Límite o riesgo
No indica si un índice específico es válido sin comprobarlo.
Ejemplo de uso
let numberOfNames = names.count
isEmpty Ver detalle
Comportamiento
Indica si no contiene elementos.
Límite o riesgo
Solo retorna Bool.
Ejemplo de uso
if names.isEmpty { print("Sin nombres") }
first, last Ver detalle
Comportamiento
Obtiene el primer o último elemento.
Límite o riesgo
El resultado es opcional.
Ejemplo de uso
let edges = (names.first, names.last)
append(value) Ver detalle
Comportamiento
Agrega al final.
Límite o riesgo
El valor debe ser del tipo Element.
Ejemplo de uso
names.append("Eva")
insert(value, at: i) Ver detalle
Comportamiento
Inserta en una posición.
Límite o riesgo
El índice debe ser válido.
Ejemplo de uso
names.insert("Rosa", at: 1)
contains(value) Ver detalle
Comportamiento
Comprueba existencia.
Límite o riesgo
Realiza búsqueda; no entrega el índice.
Ejemplo de uso
let hasAna = names.contains("Ana")
removeAll() Ver detalle
Comportamiento
Elimina todos los elementos.
Límite o riesgo
Modifica la colección original.
Ejemplo de uso
names.removeAll()
Array(repeating:count:) Ver detalle
Comportamiento
Repite un valor una cantidad determinada.
Límite o riesgo
count no puede ser negativo.
Ejemplo de uso

Set<Element>

Set<T> Ver detalle
Comportamiento
Colección sin orden estable y sin duplicados.
Límite o riesgo
T debe conformar Hashable.
Ejemplo de uso
var tags: Set<String> = ["swift", "ios", "swift"]
insert(value) Ver detalle
Comportamiento
Agrega el valor si no estaba presente.
Límite o riesgo
No existe append; no hay posición final.
Ejemplo de uso
let insertion = tags.insert("xcode")
contains(value) Ver detalle
Comportamiento
Comprueba pertenencia.
Límite o riesgo
No entrega una posición porque no usa índices enteros.
Ejemplo de uso
let usesSwift = tags.contains("swift")
first Ver detalle
Comportamiento
Entrega algún elemento.
Límite o riesgo
Es opcional y no significa “el primero insertado”.
Ejemplo de uso
let anyTag: String? = tags.first
union Ver detalle
Comportamiento
Reúne los valores de ambos sets.
Límite o riesgo
Elimina duplicados.
Ejemplo de uso
let all = Set([1, 2]).union(Set([2, 3]))
intersection Ver detalle
Comportamiento
Conserva valores comunes.
Límite o riesgo
Puede producir un set vacío.
Ejemplo de uso
let common = Set([1, 2]).intersection(Set([2, 3]))
subtracting Ver detalle
Comportamiento
Conserva valores del primer set que no están en el segundo.
Límite o riesgo
El orden de los operandos cambia el resultado.
Ejemplo de uso
let onlyA = Set([1, 2]).subtracting(Set([2, 3]))
symmetricDifference Ver detalle
Comportamiento
Conserva valores no compartidos.
Límite o riesgo
Excluye la intersección.
Ejemplo de uso
let different = Set([1, 2]).symmetricDifference(Set([2, 3]))
isSubset(of:) Ver detalle
Comportamiento
Comprueba si todos sus elementos están en otro set.
Límite o riesgo
No comprueba igualdad por sí solo.
Ejemplo de uso
let included = Set([1, 2]).isSubset(of: Set([1, 2, 3]))

Dictionary<Key, Value>

[Key: Value] Ver detalle
Comportamiento
Almacena pares clave-valor.
Límite o riesgo
Key debe conformar Hashable.
Ejemplo de uso
var ages: [String: Int] = ["Ana": 28]
dict[key] Ver detalle
Comportamiento
Lee o modifica el valor asociado.
Límite o riesgo
La lectura devuelve Value?.
Ejemplo de uso
let age: Int? = ages["Ana"]
dict[newKey] = value Ver detalle
Comportamiento
Agrega un par.
Límite o riesgo
Sobrescribe si la clave ya existe.
Ejemplo de uso
ages["Luis"] = 31
dict[key] = nil Ver detalle
Comportamiento
Elimina el par.
Límite o riesgo
Solo actúa si la clave existe.
Ejemplo de uso
ages["Ana"] = nil // Elimina la entrada
updateValue(_:forKey:) Ver detalle
Comportamiento
Inserta o actualiza.
Límite o riesgo
Devuelve opcionalmente el valor anterior.
Ejemplo de uso
let previous = ages.updateValue(32, forKey: "Luis")
removeValue(forKey:) Ver detalle
Comportamiento
Elimina por clave.
Límite o riesgo
Devuelve opcionalmente el valor eliminado.
Ejemplo de uso
let removed = ages.removeValue(forKey: "Luis")
keys, values Ver detalle
Comportamiento
Expone vistas de claves o valores.
Límite o riesgo
No se debe depender de un orden fijo.
Ejemplo de uso
for (name, age) in ages { print(name, age) }

Elección:

•
Orden, índices o duplicados → Array.
•
Unicidad y operaciones de conjuntos → Set.
•
Acceso mediante una clave → Dictionary.

Error frecuente

•
Usar índices, first! o removeFirst() sin comprobar que la colección contiene elementos. También es incorrecto depender del orden de un Set, porque ese orden no es estable.

5. ControlFlow

Abrir playground

Objetivo: decidir qué código se ejecuta, repetir operaciones y abandonar un flujo cuando no se cumplen sus condiciones.
Nomenclatura oficial Ver términos
•
Conditional Statements — sentencias condicionales.
•
If Statement — sentencia if.
•
Switch Statement — sentencia switch.
•
For-In Loops — ciclos for-in.
•
While Loops — ciclos while y repeat-while.
•
Early Exit — salida anticipada mediante guard.
•
Where Clause — condición adicional aplicada a un patrón o iteración.
•
Control Transfer Statements — continue, break, fallthrough, return y throw.

Condiciones

if condición Ver detalle
Comportamiento
Ejecuta un bloque cuando el Bool es verdadero.
Límite o regla
La condición debe ser Bool; no admite valores “truthy”.
Ejemplo de uso
if temperature > 30 {
    print("Hace calor")
}
else if Ver detalle
Comportamiento
Evalúa otra condición si las anteriores fallaron.
Límite o regla
Solo se ejecuta la primera rama verdadera.
Ejemplo de uso
if score >= 90 {
    print("Excelente")
} else if score >= 60 {
    print("Aprobado")
}
else Ver detalle
Comportamiento
Ejecuta la alternativa final.
Límite o regla
No lleva condición.
Ejemplo de uso
if isConnected {
    loadData()
} else {
    showOfflineMessage()
}

Salida anticipada

guard condición else Ver detalle
Comportamiento
Exige que la condición sea verdadera para continuar.
Límite o regla
El else debe abandonar el scope.
Ejemplo de uso
guard isAuthenticated else { return }
showProfile()
guard let Ver detalle
Comportamiento
Desempaqueta un opcional y permite usarlo después.
Límite o regla
Falla y sale cuando el valor es nil.
Ejemplo de uso
guard let user = currentUser else { return }
print(user.name)

Selección por casos

switch valor Ver detalle
Comportamiento
Compara un valor con patrones o casos.
Límite o regla
Debe ser exhaustivo.
Ejemplo de uso
switch status {
case .success: print("OK")
case .failure: print("Error")
}
case Ver detalle
Comportamiento
Define un patrón aceptado por switch.
Límite o regla
No existe caída implícita al caso siguiente.
Ejemplo de uso
switch number {
case 0: print("Cero")
default: print("Otro")
}
default Ver detalle
Comportamiento
Cubre los valores restantes.
Límite o regla
Puede ocultar nuevos casos de un enum; omitirlo ayuda a detectar cambios.
Ejemplo de uso
switch number {
case 0: print("Cero")
default: break
}
case ... where condición Ver detalle
Comportamiento
Agrega un filtro al patrón.
Límite o regla
La condición se evalúa después de coincidir el patrón.
Ejemplo de uso
switch age {
case let value where value >= 18: print("Adulto")
default: print("Menor")
}
break Ver detalle
Comportamiento
Termina el bloque o ciclo actual.
Límite o regla

Flujo completo:

enum Error          identifica los fallos posibles
throws              declara que una función puede fallar
throw               produce el fallo concreto
try                 intenta ejecutar la función
do                  contiene el intento
catch               recibe y maneja el error

Ejemplo integrado:

enum DatabaseError: Error {
    case userExists
    case invalidName
}

func saveUser(name: String) throws {
    guard !name.isEmpty else {
        throw DatabaseError.invalidName
    }
}

do {
    try saveUser(name: "")
} catch DatabaseError.invalidName {
    print("Nombre inválido")
} catch {
    print("Otro error: \(error)")
}

Diferencia fundamental:

try  + do/catch = conserva y maneja el error
try?            = solo entrega valor o nil; pierde el detalle del error

Error frecuente

•
Creer que un bloque do no comienza si después se lanza un error, usar try? cuando se necesita conocer la causa o recurrir a try! sin una garantía absoluta. do se ejecuta hasta el punto del throw; desde allí el control pasa al catch compatible.

Comprobar y convertir tipos

is — Type-Checking Operator Ver detalle
Comportamiento
Comprueba el tipo y retorna Bool.
Límite o riesgo
No convierte ni entrega la instancia tipada.
Ejemplo de uso
if item is Movie { print("Es una película") }
as — Upcasting Ver detalle
Comportamiento
Trata una subclase como su superclase o convierte de forma garantizada.
Límite o riesgo
Se pierden temporalmente los miembros exclusivos de la subclase.
Ejemplo de uso
let animal: Animal = dog as Animal

Intenta convertir y devuelve un opcional.
Límite o riesgo

Ejemplo de uso
if let dog = animal as? Dog {
    dog.bark()
}
as! — Forced Downcast Ver detalle
Comportamiento
Afirma que la conversión tendrá éxito.
Límite o riesgo
Produce error en ejecución si el tipo real no coincide.
Ejemplo de uso
let dog = animal as! Dog // Falla si no es Dog

Patrón seguro:

if let fish = animal as? Fish {
    fish.respirarBajoAgua()
}

Polimorfismo:

[Animal] puede contener Dog, Cat y Bird
          ↓
as? recupera el subtipo concreto
          ↓
permite usar el método específico

Reglas:

•
is pregunta.
•
as sube hacia un tipo más general.
•
as? intenta bajar de forma segura.
•

•
Type casting cambia la vista tipada de una instancia; no crea otro objeto.

Error frecuente

•
Confundir type casting con conversión de valores. as? no transforma "123" en Int; para eso se usa Int("123"). Un downcast forzado con as! termina la ejecución si el tipo real no coincide, e imprimir una función que retorna Void solo muestra ().

Abrir playground

Objetivo: seleccionar una de dos expresiones cuando la decisión es breve y produce un valor.
Nomenclatura oficial Ver términos

False Expression — expresión elegida cuando la condición es falsa.

Sintaxis y decisiones

condition ? A : B Ver detalle
Comportamiento
Evalúa condition y ejecuta solo una de las expresiones.
Límite o riesgo
La condición debe ser Bool.
Ejemplo de uso
let status = isConnected ? "En línea" : "Sin conexión"
let value = condition ? A : B Ver detalle
Comportamiento
Produce un valor para una asignación.
Límite o riesgo
A y B deben tener tipos compatibles.
Ejemplo de uso
let access = age >= 18 ? "Permitido" : "Denegado"
Ternario anidado Ver detalle
Comportamiento
Evalúa otra condición dentro de una rama.
Límite o riesgo
Pierde legibilidad rápidamente.
Ejemplo de uso
let category = score > 90 ? "A" : score > 70 ? "B" : "C"
condition ? action() : () Ver detalle
Comportamiento
Usa () como rama sin acción útil.
Límite o riesgo

Ejemplo de uso
isReady ? start() : ()
Asignaciones en las ramas Ver detalle
Comportamiento
Modifica una variable según la condición.
Límite o riesgo

Ejemplo de uso
let color = hasError ? errorColor : normalColor

let status = isConnected ? "Conectado" : "Desconectado"

Usar ternario para elegir valores breves. Usar if-else para varias instrucciones, ternarios anidados o cambios de estado.

Error frecuente

•
Usar el operador ternario para efectos secundarios o anidar varias decisiones hasta volver ilegible la expresión. Debe elegir entre dos valores breves; para ejecutar acciones o explicar lógica compleja se prefiere if-else.
